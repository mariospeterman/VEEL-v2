## SUP-01 — Enterprise staging proof claims provider evidence without checking it

**Confirmed P1/P2 release-evidence defect, not a production authorization bypass by itself.** `apps/api/scripts/prove-enterprise-managed-creators.mjs:6-7` requires KYB and Enterprise contract evidence IDs, but `:10` only checks they are nonempty. The IDs are never passed to an API, looked up, compared with the current organization/entitlement, checked for approval/revocation/expiry, or included in a verifiable release evidence reference. `:25-29` makes three projection GETs; `:35-49` checks projection booleans and a literal finance-boundary string. `:57-61` then prints `state: PROVIDER_PROVEN` and labels both evidence fields `configured_redacted`. It does not prove that these projection states came from authentic provider callbacks or approved commercial evidence, and `reporting.totals` can even be absent/non-array while the proof passes with zero buckets.

**Reproduction:** Ran the exact 75-line script in an isolated async-function wrapper with a synthetic process-env proxy and fetch implementation; no network requests, external service access, or source changes. Used evidence IDs `does-not-exist-kyb` and `does-not-exist-contract`. The only requests were organizations, relationships, and relationship reporting projections. Each evidence ID was accessed once, solely for the initial nonempty check. The script emitted `PROVIDER_PROVEN`. Full output: `/workspace/scratch/0635fbdaf32f/supplemental-enterprise-proof.json`.

**Impact:** A release pipeline can present API fixture/manual-override readiness as authenticated provider proof. `docs/v2-new-build/enterprise-managed-creators.md:66-76` says local mocks prove application behavior only and requires real callbacks/approved evidence for the production gate. A nonempty identifier is not that evidence.

**Fix:** Keep this read-only script as an explicitly named projection smoke check unless/until it validates authorized, minimized provider-event/KYB record and commercial-approval evidence by exact ID, subject, environment, current status, expiry/revocation, and exact release artifact. Bind verification to normalized canonical records rather than raw sensitive provider payloads. Validate the reporting response shape before calling it proven. Record distinct statuses for projection smoke, provider proven, and launch approval; do not fabricate approval from booleans. Add a meaningful negative test: random/mismatched/revoked evidence IDs fail even when dashboard booleans are true. Keep provider credentials and private evidence out of logs.

## Existing findings whose current tests do not establish their guarantees

These are test-remediation notes for existing findings, not additional product bugs:

- **AUTH-08, OAuth single-use atomicity:** `apps/api/test/mcp.test.ts:1009-1039` verifies sequential code reuse rejection only. The fake at `:1605-1611` returns the same mutable authorization-code object and mutates `usedAt` in memory. It does not exercise database snapshots, competing redemption transactions, or insertion failure between mark-used and issue-token. Add an actual-Postgres concurrent redemption and rollback regression when fixing the authority; both requests must not mint usable tokens.
- **AUTH-10, durable idempotency:** `idempotency.test.ts:11-56` correctly tests header parsing and stable payload hashing. It never claims to persist a receipt. Route/repository receipts, payload conflict, stale retry after newer mutation, cross-actor isolation, and concurrency need integration coverage for the mutations listed in AUTH-10; passing helper tests is not evidence those routes are idempotent.
- **AUTH-11/18, actual repository SQL:** `postgres.test.ts:5-32` tests transaction-helper delegation/error propagation using a mocked `begin`; `app-dependencies.test.ts:8-38` tests pool ownership and closure. Neither parses or runs operational SQL. Preserve these useful narrow tests, and add database regressions for the concrete admin pagination and ambiguous live-room query defects.
- **MCP authorization/media:** `mcp.test.ts:1111-1174` gives every request an active profile, verified age and a linked wallet; `:1230-1235` grants all admin permission checks. The suite usefully proves protocol negotiation, origin filtering, scoped tool visibility, private drafts, redaction, media capability paths, sanitization and compensation, but it does not prove role-permission revocation or ineligible-user behavior through real SQL. Add focused negative integration cases alongside the relevant authority fixes rather than broad duplicate mocks.
- **Telemetry:** `telemetry-routes.test.ts:6-19` is named as an attribute-retention check, but only asserts that a custom recorder receives an object containing name/value. Current `telemetry-routes.ts:24-28` correctly omits the unique ID from metric attributes; test that actual exported/observed metric-attribute boundary if retention is changed. This is a regression-test weakness, not a current confirmed ID leak.

## Positive and bounded observations

The enterprise script performs GETs only and does not mutate staging organizations, memberships, payments, or provider state. It enforces HTTPS outside localhost and does not print the session cookie. However its fetches have no explicit timeout; a stalled upstream can leave proof execution hanging. Add a bounded abort timeout as part of normal proof-runner robustness.

Provider replay runtime tests cover important canonical payment write guards, missing media targets, retryable unconfirmed settlements, provider alias preservation, and playback-observation cutoffs. They are appropriately dependency-isolated unit tests and are not live-provider proof. Profile-dashboard tests correctly cover revoked KYC and expiry equality at a supplied clock. Health tests separate liveness from database readiness and check sanitized errors.

No repository tests were rerun by this reviewer because root owns the repository/toolchain baseline. The isolated script reproduction ran host Node 24.22.1; the project pins Node 22.16+ below 23. No provider staging credentials, signed callbacks, mobile-wallet hardware, or Mac worktree changes were available. No source files changed.
