# app.test.ts middle-range audit

Exact commit: `71ceabcfaa8a5258e1b935a391ff4e6e7330c682`. Assigned and fully read: lines 5001–10000, 5,000 lines / 160,259 bytes, in eight untruncated sequential tool outputs. Source unchanged. Coverage identity and ranges are in `app-test-middle-coverage.json`.

No additional runtime defect is asserted beyond the existing domain audit. The concrete findings below explain how specific passing tests miss already-confirmed implementation defects; they belong in remediation acceptance criteria, not a second vulnerability count.

## Precise test replacements/additions needed

1. **Publication fixture supplies an owned draft the real ready-state query cannot return.** `apps/api/test/app.test.ts:5038` names provider-ready publication but stubs `findOwnedContentForUpload` unconditionally and `publishOwnedContent` returns `homeFeedItem`. It never runs the actual state-filtered owned lookup or an upload→ready transition. This masks CONTENT-01. Keep route-response coverage, add a full-migration repository/API test that creates an asset, applies provider-ready status, submits review and verifies the first HTTP call succeeds.

2. **Image upload success stops before any authorized image delivery projection.** `:5448` proves decode/EXIF removal, reservation and provider upload with `findContentDetail` intentionally throwing. It never asks for a resulting image URL or renders bytes. This masks CONTENT-19, where newly completed private images have no poster/delivery URL. Add a real unseeded image lifecycle through review, authorized feed/detail resource, short-lived CDN signing, denial and expiry; do not seed `posterUrl` as the starting condition.

3. **Webhook dedupe test bypasses the partial-commit boundary entirely.** `:6291` returns `false` directly from `recordMediaProviderWebhook` and asserts no application. It proves route branching only; it cannot distinguish an already-applied event from an orphan receipt created before event persistence. This masks CONTENT-03/PAY-06. Add fault injection between receipt insert and normalized-event insert and verify durable redelivery/replay repairs the first incomplete attempt exactly once.

4. **Notification enrollment fixture accepts an arbitrary endpoint and invalid placeholder keys.** `:7075` sends `https://push.example.test/token`, `browser-public-key`, and `browser-auth-secret`, stubs registration, and asserts redacted successful JSON. It proves response secrecy but establishes no supported push-service URL/key validation, device ownership on re-registration, preference revocation, or worker dispatch. This masks WA-01/WA-02/WA-04. Retain response-redaction tests while adding real registration validation and account A→B pending-delivery tests with valid generated key material; private egress denial and total transport timeout must be separate worker proofs.

5. **Event and Mutuals happy paths never execute their failing SQL.** `:7420` stubs event creation with `eventFixture`; `:7732` stubs Mutuals feed with `mutualsFeedItemFixture`. Both return success without exercising the first-insert CTE projection or the nonexistent `content_items.media_kind` column. This masks CONTENT-08/09. Add migrated-database API smoke for first create/update responses and an empty as well as populated Mutuals feed, because PostgreSQL validates the invalid column even with zero result rows.

6. **Header presence is used as a proxy for lifetime idempotency.** `:8906` checks a support-policy mutation without a key returns 400; similar tests cover refund/feature flag/organization mutation headers. They do not replay the same key after an intervening newer command, nor reuse it with changed body/target. This masks AUTH-10 and CONTENT-17. Require real persistence tests for A→B→replay A and same key/different target or payload, with original-result replay and 409 conflict semantics.

7. **Last-owner test delegates the invariant to a prearranged exception.** `:9502` makes `updateOrganizationMember` throw `AdminRepositoryStateConflictError` and only verifies its HTTP mapping. It cannot expose AUTH-20's concurrent two-owner removal race. Add two real concurrent database mutations and assert at least one current active owner remains, including demotion and suspension variants.

8. **Operations projection fixtures prefill nonempty identities/live/AI rows that real queries cannot produce.** `:9537` stubs every admin repository and asserts live rooms, legacy identity fields and legacy AI session/tool-call rows. This does not test AUTH-18's ambiguous live query, AUTH-19's old identity table, or AUTH-21's missing current MCP audit data. Add current-provider verification and current MCP connection/tool-call records through canonical owners, then query admin projections on the actual schema. Reject unknown/sensitive fields explicitly; do not simply copy old fixtures into new canonical tables.

9. **Legacy AI success tests preserve canned execution semantics.** `:7949` calls the real fixed `prepareToolResult` with a fake repository, then asserts state `executed` and a static summary without any backend data dependency. This corroborates ROOT-08's product gap. Decide whether to retire these endpoints or bind retained tools to actual canonical facts; tests must reflect that decision rather than requiring a successful canned result.

These tests are useful route-unit tests. None of the observations says to remove mocking everywhere or duplicate an entire integration suite for each route. Target actual SQL, retry/concurrency state transitions, provider request/response contracts, and observable user outcomes at the boundaries where the current fixtures bypass the defects.
