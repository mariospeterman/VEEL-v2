## Additional concrete test defect

**TEST-01 — Explicit null live-provider fields silently become populated fixture defaults (P2, test fidelity).** At `apps/api/test/app.test.ts:12574`–12577, `liveRoomFixture` uses `overrides.providerStreamId ?? "livepeer-stream"` and the same pattern for playback ID, host ingest URL and host stream key. The reservation tests starting at10460,10568,10645 and10725 explicitly pass null for these fields, intending to represent a reserved room before provider attachment. Those fixtures actually carry provider identifiers and host secrets. This is a reproducible mismatch between the tested state and the described lifecycle, not an assertion that the production route skips provider creation. Preserve explicit null with `overrides.field === undefined ? defaultValue : overrides.field`; assert the reserved shape and provider-creation claim state directly. The fixture factory should support all actual nullable states.

## Review boundaries

The file has useful negative cases for authentication, key presence, scope handling, signature failure, provider failure cleanup and response secrecy. The defects above do not justify removing those tests or replacing every mock with a live provider call. The missing evidence is concentrated in real SQL, identity separation, state transitions, retry/concurrency behavior and exact provider contracts.

The Persona rotation header parser was investigated separately against primary documentation; this report does **not** assert a new rotation bug or a mandatory replay-tolerance rule without a proven failing supported payload. No additional production runtime issue was confirmed by this test-file review beyond the existing domain reports. TEST-01 is a separately actionable test-factory correction.
